### Device preview (Phase 6A: preview and diagnosis only, no responsive redesign)

Inspect the real landing page and login at mobile / tablet viewport sizes without resizing the browser. Development builds only (`DEV_PREVIEW_ENABLED` in draft-tools/devPreviewFlag.ts, the same rule as the other preview controls); in a production build the URL parameters are ignored and no control is rendered.

- Open: on `/draft/landing` use the **Device** pill at the top (login closed) or the **Device** row of the Preview panel inside the login dialog. Presets: Mobile Small 375 x 667, Mobile Standard 390 x 844, Mobile Large 430 x 932, Tablet 768 x 1024, plus Custom (width x height, 240-1600). **Desktop** returns to the normal page.
- How it works: the URL of the ONE landing route selects the mode (`?device=...` host, `?embed=1` the real page inside the host's iframe, `?open=1&lang=&state=&flat=1` the login selections). The host is a toolbar plus an **iframe of the same route with exactly the device's CSS size**, so real media queries / viewport units respond (a scaled-down desktop page would not). The host does NOT mount the landing page itself, so there is only ever one 3D engine: the one inside the iframe; every device switch builds a fresh iframe (the old one is emptied first). If the viewport is larger than the window the area scrolls; it is never shrunk.
- Controls (all outside the simulated viewport): Device, Login Open / Close (Close rolls the sheet up like Esc), Lang, Mode (3D scroll / Flat fallback), State (5 preview states). They survive device switches, reloads (URL) and "Desktop".
- Host <-> iframe: same origin, no postMessage. The host dispatches a CustomEvent on `iframe.contentWindow`; the embedded page dispatches status events on its own window (`previewBridge.ts`). The in-page Preview panel and launcher are not drawn inside the simulated viewport, and the global "Back to Dev Tools" badge is hidden there (embedded page only).
- Limits: the iframe has the same user agent, pixel ratio, mouse input and no browser toolbars / safe areas as the desktop window, so touch-only media (`hover: none`, `pointer: coarse`), `env(safe-area-inset-*)`, dynamic mobile toolbars (`dvh`) and real devices' font scaling are not reproduced. The Next.js dev indicator is drawn by Next itself.

### Preview the flat fallback card

The flat fallback card (a flat parchment card instead of the 3D scroll) is normally shown only when the 3D scene fails to start (`sceneError` from `useScrollLoginAnimation`, e.g. WebGL unavailable). In the draft preview panel (bottom-left, dev builds only) the **Mode** row switches between **3D scroll** and **Flat fallback** without disabling WebGL: it sets a preview-only `forceFlat` state in `LoginModal.tsx` (`flat = sceneError || forceFlat`) and reuses the same card, typography and notice as the real fallback. The 3D canvas is hidden (not unmounted) while the flat card is forced, so switching back needs no reload. If WebGL really fails, "3D scroll" is disabled. Closing while forced waits for the hidden scroll to roll up (~1.4 s), like the normal close.

Notice placement (3D scroll AND flat card): the login notice (error / unverified / generic) is rendered INSIDE the form, in normal flow, between the divider and the first label (`LoginModal` passes one element to `LoginForm` through the `notice` slot, `ClassicLoginLayout` renders it). It used to sit under the bottom roll on the 3D scroll; that placement and its `placement` prop, `--notice-offset` and `--notice-max-width` are gone. No emoji or icon. Look (`classic/ClassicLogin.module.css`): square, the inputs' fill and border, a 3px left rule chosen by `data-tone` (ink red `#8a2a1f` for error / generic, amber ink `#a8742a` for the unverified e-mail), text `#4a3520`, no shadow, the "back to sign up" link styled like the sign-up link; typography group `--notice-*` (Jost, IBM Plex Sans Thai, 13px). No space is reserved when there is no message: the 3D paper grows by exactly what the message adds (see "Paper size, form spacing and quill"), and the flat card just wraps its content.

scroll/ and quill/ are used only by the login dialog (LoginModal; page.tsx only calls the scroll hook's preload/release), so they live inside login-ui/.

### Typography of the login UI

The login UI has ONE typography file. Edit the variables in its sections 1-3; do not edit the last section ("applied rules").

- Classic: `_components/login-ui/classic/ClassicLoginTypography.module.css`
- Five groups (set through `data-typo` on the elements): **heading** (h2), **body** (labels, "remember me", "forgot password", "no account?" prompt, sign-up link), **input** (typed text and placeholder), **button**, **notice** (error / unverified banner: fully independent, inherits nothing from body).
- Per group, six properties: `--<group>-font-en` / `-font-th` (Latin font / Thai font; fallbacks are appended by the file), `-weight`, `-size`, `-letter-spacing`, `-line-height`, `-word-spacing`.
  Change `--body-*` once and every body text follows (the notice does NOT follow: it has its own `--notice-*`). The placeholder always follows input.
- Exceptions (values that really differ from body): label (`--label-weight/-size/-letter-spacing`) and sign-up link (`--signup-weight` = 500). Everything else of those elements is inherited from body.
  Example, heading letter-spacing: `--heading-letter-spacing: 0.05em;` in ClassicLoginTypography.module.css.
- Thai vs English: `.typography:lang(th)` / `:lang(en)` blocks override any variable per language (the language is the `lang` attribute on the `LoginModal` root; on the live site the same CSS works with `<html lang>`) (the English button weight, 4px letter-spacing and 0.8 text scale live there).
- Flat fallback card (WebGL unavailable, Classic only): no separate typography values any more (the old `.typography.flatCard` block with larger sizes is gone, section 4 of the file is empty); it uses the same fonts and sizes as the scroll.
- Not in the typography files: text colors (className in the layouts), `text-transform: uppercase` on labels and the checked-checkbox mark size (`.parch-label`, `.parch-check:checked::after` in src/styles/globals.css, read-only), spacing/padding/sizes (the layout files, below).
- Specificity: the files' rules use `.typography [data-typo=...]` (0,2,0) and win over `.parch-*` / `.font-*` in globals.css and over Tailwind utilities (those are in @layer, so any un-layered rule beats them).

### Typography of the landing page (per-language fonts)

One section of the shared `src/styles/globals.css` ("Landing page typography (per-language fonts)", class `.landing-typography`; it used to be a draft-local CSS module and was moved at the dev's request). It uses the same convention as the login typography file: per-role variables `--<role>-font-en` (Latin glyphs) and `--<role>-font-th` (Thai glyphs), a section of per-language overrides, and an "applied rules" section that is not edited. The language is the `lang` attribute on the page root in `page.tsx` (`lang={lang}`) and the rules use `:lang(th)` / `:lang(en)`, so on the live site (where `<html lang>` is already set by next-intl) the CSS needs no change. Do not create separate th / en CSS files.

- Default for both languages: **Google Sans**.
- Roles (`data-typo` in `page.tsx`): `brand`, `langtoggle`, `welcome`, `title`, `subtitle`, `auth` (login and sign-up buttons), `realtime`. The buttons' variables are named `--button-*` (like the login dialog), but their `data-typo` stays `auth`: the login dialog is rendered inside the landing root and has its own `data-typo="button"`, so using the same value would make the landing rules (and the English text scale) reach the dialog's button.
- English overrides: welcome, subtitle and realtime = Josefin Sans; title = Jim Thompson Roman; buttons = Montserrat, weight 500, letter-spacing 4px, label scaled 0.8 (`--button-text-scale`, applied to the `<span>` around the label in `page.tsx`, which is `display: inline-block` so the transform works; the button box keeps its size).
- Thai overrides: welcome, title and buttons = Jim Thompson Roman; subtitle and realtime = IBM Plex Sans Thai. **Always set BOTH slots (`-en` and `-th`) in the `:lang(th)` block:** the chain is `var(--x-font-en), var(--x-font-th)` per glyph and the `-en` default (Google Sans) has Thai glyphs, so an override in `-th` alone is never reached. These fonts all have Latin and Thai glyphs. Brand and toggle stay Google Sans.
- Button defaults (Thai and any language without an override): weight 400, letter-spacing 0.15em, scale 1 (= the old look).
- Welcome line size: `--welcome-size` (20px, phones) and `--welcome-size-sm` (24px, from 40rem = Tailwind `sm` up) in section 1 of the `globals.css` block, same for both languages (it was `text-2xl sm:text-3xl` = 24 / 30px). Its line-height stays `leading-8 sm:leading-9` in `page.tsx` so the column does not shift. To make it differ per language, override the two variables in the `:lang(th)` / `:lang(en)` blocks.
- Everything else (size, weight, letter-spacing, colour of the other roles) is still a Tailwind utility in `page.tsx`; the button weight / letter-spacing / scale are variables as described above. To vary another property per language add `--<role>-<property>` to section 1 of that `globals.css` block and override it in the `:lang(...)` blocks.
- The inline `fontFamily` that the auth buttons used to carry (`AUTH_BTN_STYLE`) and the `tracking-[0.15em]` utility on `AUTH_BTN` were removed: font, weight and letter-spacing of the buttons now come from the module (an inline style would beat it).

### Paper size, form spacing and quill on the 3D sheet

Sizing (`login-ui/scroll/sheetLayout.ts`, `computeSheetLayout`; plain TypeScript with no three.js import, used by the engine through `applyLayout()` in `scrollLoginAnimation.ts` and by the flat card through `shared/useFlatSheetSize.ts`): the sheet height is `min(max(h * 0.49 * SHEET_TALLER, 445 * SHEET_TALLER) + SHEET_EXTRA_PX + noticeExtraPx / 0.9091, h * 0.92)` with `SHEET_TALLER = 1.1` (paper 10% taller than before) and `SHEET_EXTRA_PX` (currently 26.4). The width is kept in pixels as it was before the paper was made taller: the model is stretched on X by up to `SHEET_WIDTH_SCALE` (1.2) but never wider than 96% of the window, then `widthScale` re-expresses that width for the taller model (about +4% on a 1280x928 window, about -10% on a 390px and -14% on a 375px phone). Only X is scaled: the GLB's only animation channel is the morph weights, the roll cylinders just get longer, the texture stretches by the same factor.

**Coupling rule:** `SHEET_EXTRA_PX` pays for the extra space inside the form. The form is centred in the flat-paper area, which is 90.91% of the sheet height (the bottom roll is the rest), so `SHEET_EXTRA_PX = (extra px of --heading-margin-top over 1rem + --prompt-margin-bottom in px) / 0.9091`. Today: (2rem - 1rem = 16px + 0.5rem = 8px) / 0.9091 = 26.4px. Change either variable and update the constant, otherwise the gaps above and below the form change.

**Login message:** `noticeExtraPx` is how much height the message adds to the form: its height plus its top margin, measured from the live element by `shared/useNoticeExtra.ts` (a `ResizeObserver`, so 1 to 3 lines, Thai / English and window width are handled; 0 with no message; 57px for the 2-line unverified-e-mail message at 1280x928). `LoginModal` forwards it to the engine (`setContentExtra`, eased over ~180 ms, instant under `prefers-reduced-motion`) so the paper grows by `noticeExtraPx / 0.9091` and the gaps above and below the form stay exactly what they are without a message; the width does not change. Measured at 1280x928: 526.6px idle, 606.9px with the unverified message (+80.3), gaps 34.4px both ways, no inner scrollbar (1366x768: 515.9 / 596.2px, gaps 29.5px). Where the 92%-of-window cap binds (window shorter than about 660px) the paper cannot grow further and a long message can scroll slightly.

**Tablets (window width 640 to 979px, `TABLET_MIN_WIDTH` / `TABLET_MAX_WIDTH` / `SHEET_TABLET_HEIGHT_SCALE` in `sheetLayout.ts`):** the form has a fixed height, so on tall portrait tablets the empty band above the title and below the sign-up line grew with the window (58px at 768x1024, 96px at 820x1180, against 34px on a 1280x928 desktop). On these widths the viewport-driven part of the sheet height is multiplied by 0.92 (never below the minimum sheet, so the gap never goes under 29.5px); the width in px is unchanged (the model is stretched a little more to keep it). Measured: 768x1024 paper 487.1 x 534.2px (was 578.3), gap 37.8px; 834x1112 577.8px, gap 57.7px; 820x1180 611.5px, gap 73px; 640x960 stays 515.9px (minimum). With the unverified message the paper still grows by (noticeHeight + 16) / 0.9091 on top of that (768x1024: 614.5px, gaps 37.8 / 37.9px, no inner scrollbar). Phones (under 640px) and windows of 980px and wider (desktop, landscape iPad) are unchanged; so the paper height steps at 979 / 980px (571.9 / 619.3px at x1100). The quill is hidden on all tablet widths (existing rule).

Form box (`classic/ClassicLoginLayout.module.css`, section 1): `--sheet-padding` 2rem is the fixed space between the content and the visible paper edge; `--sheet-inset-x` (3% of the box width: the flat paper edge is inside the box), `--sheet-inset-top` (0) and `--sheet-inset-bottom` (9.09% of the box height: the roll) are derived from `--sheet-w` / `--sheet-h`, which the engine publishes; `--form-max-width` 23rem. The form box is centred above the roll (`margin-bottom` = inset + `--form-margin-bottom`) and its max height is the area above the roll, so on short windows the gaps shrink instead of the form scrolling. Spacing inside: `--heading-margin-top` 2rem (original 1rem + 16px), `--heading-margin-bottom` 1rem (merges with `--divider-margin-top` 0.55rem, so the visible gap is 1rem), label top 1.125rem, options top 0.925rem, sign-up top 1.075rem (each +2px), `--prompt-margin-bottom` 0.5rem. The flat card keeps its own values (`.layout.flatCard` sets heading bottom and prompt bottom to 0).

### Pre-loading the scroll and the quill (so the first click does not stutter)

What happens before the visitor clicks Login:
- **At HTML time** (`login-ui/scroll/preloadLoginAssets.ts`, called from `LandingDraftRoute`, which also runs on the server): `react-dom` `preload` writes `<link rel="preload">` for the 53 MB model (`as: "fetch"`, `crossOrigin: "anonymous"` to match GLTFLoader's fetch, `fetchPriority: "low"`) and the quill image (`as: "image"`, low priority, only `media="(min-width: 980px)"`). These start before hydration and before the engine chunk has loaded; the engine's own fetch reuses the response. **Keep the model hint at low priority**: at normal priority it competed with hydration and scripts (measured below).
- **When the browser is idle** (at most 1 s after mount, `requestIdleCallback`; also on `pointerenter` / `focus` of the Login button) `preloadScrollLogin()` (`useScrollLoginAnimation.ts`): imports the engine chunk, builds the renderer, parses the model and warms the GPU, **fetches and `decode()`s the quill image and keeps the `Image` in a module variable**, and calls `document.fonts.load()` for the login faces the landing page may not have used yet (IBM Plex Sans Thai 400 / 500 Thai and Latin, Jost, Prompt, Montserrat 500, Jim Thompson Roman, Google Sans), so the text does not re-flow when the form fades in.
- **Quill only where it is visible:** `quill/useQuillWanted.ts` (`min-width: 980px`) — `LoginModal` renders the feather and its two shadow copies only there. Before, the CSS hid them below 980px but the browser still downloaded the image of a hidden `<img>`.
- **Quill image:** `public/assets/landing/quill/midnight-arcane-quill.png` was resized from 1536 x 1024 (1.39 MB) to 960 x 640 (0.32 MB), same aspect ratio, so no CSS offset changed (it is drawn 478 px wide, about 2x for a retina screen).
- `preloadLoginAssets.ts` imports `preload` from `react-dom`; the project has no `@types/react-dom`, so `scroll/react-dom-preload.d.ts` declares just that function (delete it if the types are added).

Measured in headless Edge with the network throttled to 5 MB/s, CPU x4, cache off (software WebGL, so only request timing and main-thread tasks are meaningful; run-to-run variance is large):
- Fonts: the four faces that used to be requested 0.8 s AFTER the click (IBM Plex Sans Thai x2, Montserrat, Prompt) are now requested before it; no font request remains after the click.
- Quill image: now loaded before the click (311 kB instead of 1.36 MB), including in the "click right after load" case where it used to be fetched late.
- Click 2 s after load (cold): the model download now starts at page load instead of at the click; click-to-usable-form went from 34.4 s to 23.8 s in the cleanest run (30.0 s in another run; the download is still the dominant cost).
- Priority: model preload at LOW priority finished at 22 s; at normal priority it finished at 60 s and blocked the main thread for 12 s. Low is correct.
- Not confirmed: a main-thread stall when the quill appears (no long task at that moment); a one-time block of about 650-755 ms (throttled x4, so roughly 160-190 ms on a normal CPU) at the first click remains (dialog + engine mount); the second open is about 50-125 ms.

Not solved by pre-loading: the **53 MB model**. Anyone who clicks before it has downloaded and been parsed still waits for it (about 9 s at 50 Mbit/s). Shrinking it (meshopt / quantization, 1024 px textures, fewer or smaller morph targets) is a separate task that needs a visual comparison.

### Responsive rules today (inventory for the mobile design, Phase 6)

There is no mobile design yet and no mobile CSS. The only responsive rules that exist: (1) flat card / flat page padding step at 40rem (`.flatCard`, `.flatPage`, moved from Tailwind `sm:`); (2) the 3D form box is the paper width minus a fixed 32px padding from the visible paper edge (max 23rem) and at most the height of the area above the bottom roll, inside a dialog box the engine sizes from the container height and width (the paper keeps its pixel width, squeezed by about 10-14% on phones so it stays on screen); (3) the 3D notice has `max-width: min(92vw, 26rem)`. Properties that will need independent mobile values (set them in the layout file, and in the typography file for text): form-box width / max-height / side padding, heading margin, label / input / button spacing and heights, options row gap, prompt margin, notice offset / max-width / padding; flat card padding and max-width. The draft Preview panel has its own responsive classes (draft-only, not part of the product).

Where to edit what (other):

- Non-typography look: `classic/ClassicLogin.module.css` and `classic/ClassicLoginLayout.tsx` (colors); shared `.parch-*` classes live in `src/styles/globals.css` (read-only).
- Shared logic: `login-ui/shared/LoginForm.tsx`.

Why the GLB is not under public/: src/proxy.ts (shared) sends any URL whose extension is not in its static list through i18n, and
`.glb` is not in the list, so `/assets/...glb` is rewritten to `/en/assets/...glb` and 404s. It therefore stays a bundler asset
resolved with `new URL(..., import.meta.url)` in \_utils/assets.ts. Adding `glb` to that matcher would allow moving it.

## 1. What this page is

Revision of the already-live landing page `/`. The login button now opens a 3D parchment scroll (Three.js, from the Kimi "Fantasy Parchment Scroll Demo") over the village scene: it unrolls from a roll, settles with a damped wobble, then the login form fades in on the sheet; closing (X / backdrop / Esc) rolls it back up before dismissing. If WebGL or the model fails, a flat parchment card with the same form is shown. The form matches the round-2 screenshot and contains draft-only login state previews. The current working copy also has a draft-local TH/EN landing-copy toggle outside this round's requested popup scope. See `DESIGN-REQUEST.md`.

## 5. Needs dev (couldn't be done inside the draft)

- **Dependencies:** add `three` and `@types/three` (0.187.0 installed locally for this round) to `package.json`. `three` is only imported from `_components/login-ui/scroll/scrollLoginAnimation.ts` via dynamic `import()`.
- **Model asset:** `Parchment_Rolling_Animation.glb` (**56 MB**: mostly the 40 morph targets plus 13 MB of PNG textures; needs compression/CDN/preload before production) currently lives in the draft's `_assets/` and is resolved with `new URL(..., import.meta.url)`. When promoting, simplest is `public/assets/` + a plain `/assets/…glb` URL (or keep the bundler asset). Consider preloading it (e.g. on login-button hover/focus) since first open waits on the download.
- **Google Sans site-wide (already in `globals.css`):** Google Sans (Latin + Thai) is imported there and the landing typography rules (`.landing-typography` + `data-typo` roles) live there too, so nothing has to be moved on promotion; reuse the class and roles in `src/views/public/landing`. Side effect to check on live pages: about 30 `.font-*` utilities use `'Google Sans'` as their fallback, so Latin characters that the first font lacks now render in Google Sans instead of the browser default.
- **Intermittent request cancel:** in headless Edge + SwiftShader the model request was sometimes cancelled right after the WebGL context started ("Failed to fetch", ~50% of runs). `ScrollLoginAnimation.loadModel()` retries up to 2 more times (250/500 ms); all test runs then loaded the 3D sheet. Verify on real GPUs/browsers; the flat fallback covers a total failure.
- **Performance:** CPU vertex deformation per frame (~42k vertices) plus `SSAOPass`; `delta` is capped at 0.2 s per frame so very slow devices animate slower than real time. Consider dropping `SSAOPass` on low-end devices (AO is also baked into vertex colours).
- Apply the dialog and its scoped animation to the live landing page; no global CSS or shared-component change is required by the dialog.
- Connect submit to `authService.login({ usernameOrEmail, password })`, preserve the live 403/verify and generic error mapping, then `router.push(routes.dashboard)` on success.
- Remove the Preview state switch and draft-local landing language toggle; use the existing live language switch, locale-aware navigation, and `useTranslations` namespaces.
- Add the loading label "กำลังโหลด" (screen-reader only). There is no close-button label any more (the X was removed in round 4); consider an accessible close affordance for screen-reader/keyboard users if dev wants one (Esc works). Existing form strings can reuse the `login` messages.
- "จดจำฉัน" remains unsent, matching the current live login behaviour.
